原始抓取：`tmp/console-bl11831361.txt`。

## 1. 这一轮想做什么

`porting/display` 的完成条件第二半是「面板在最高、最低和设定档上都有可见变化」。探针
`package/BacklightProbe.cpp` 已实现该测试：三次亮灭，然后 `0x7ff`、`0x40`、设定档各停两秒。
`alioth-bl=3` 是完整模式。

本轮同时把设定档的默认值从 `kMaxLevel` 改为 `0x300`，好让一轮里三档互不相同。

## 2. 读数：桌面没有出现

```
SUPER t=190s ... sw=0/0/0 own=0 prep=0 mon=11 wdt=1/190
CPUT  t=190s irq=1390707 ipi=131249 sent=131255 | c0=127037/34 c1=17/23 c2=192/18
      c3=37/11 c4=463895/74367 c5=693747/53226 c6=96499/3315 c7=9348/255
      run=7 deaf=1e st=00
PANEL nonblack=911/1000 luma=43
```

- `deaf=1e`：四位被置起，四个核不再处理中断。
- `mon=11`：`boot_log_tick` 只跑了 11 次。这一行是每秒一次的，所以它在第 11 秒后就不再执行——
  它自己的线程睡在一个失聪核的定时器队列上。
- `sw=0 own=0 prep=0`：显示路径从未建立，桌面没有出现。
- `c1/c2/c3` 的计数停在十几到几百，`c4/c5/c6` 却到了几十万，说明失聪的正是低位那几颗。

## 3. 结论

**DSI0 的 TPG 命令 FIFO 写路径在这块板上会把执行它的核挂住。** 这与记录里此前只作为推断
写下的那句话一致（「厂商 FIFO 通路只在 secure_mode 下运行」），但这次是读数，不是推断：

- 之前亮度「没有硬件验证」的状态结束于此，结论是**不可用，且会连带毁掉整轮启动**。
- 这也解释了为什么探针从来只在主机测试里跑过：主机测试能验证包的字面值，验证不了发出它的通路。

## 4. 边界

- 本轮无法区分「写亮度的包挂住了核」与「亮灭循环里的 `panelBlink` 挂住了核」，两者都走
  DSI0。下一个能分开它们的实验是只测 `panelBlink` 或只测一次 `writeBrightness`，各一轮。
- `deaf` 与本轮之前的失聪核是同一个症状，但成因不同：那次是 GMU 忙计数器，这次是 DSI0。
  两者都说明同一件事——在这块板上，读或写一个没有时钟、或只在 secure world 下可用的窗口，
  不会失败，而是不返回。
- 因此 `alioth-bl` **不应进入任何 release 镜像的默认参数**。本轮之后它仍只在显式传入时启用。
