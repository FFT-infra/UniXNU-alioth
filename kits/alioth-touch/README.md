# alioth-touch: K40 (SM8250) FocalTech FT5652 touch kit

Board bring-up for the FocalTech FT5652 SPI panel fitted to the Redmi K40
(M2012K11AC, alioth). Chip facts were read off the device (Android, root):

- IC ID **0x5652**, FocalTech FTS SPI protocol, 10 contacts, 12-bit coordinates
- Touch SPI on **QUPv3 wrapper 0 SE4** @ `0x990000` (of `0x980000 + SE*0x4000`),
  6 MHz, CS0; pins GPIO 8/9/10 (MISO/MOSI/CLK, function `qup4` = FUNC_SEL 0)
- IRQ GPIO 39 (level/low), reset GPIO 101 (active low) — the frame loop polls,
  so the IRQ line is only left configured as an input
- Clocks: GCC vote `0x52008` bits 6/7/8/9/14 (m_ahb/s_ahb/core/core_2x/SE4),
  halts `0x17004`/`0x17008`/`0x23000`/`0x23008`/`0x174cc`, SE4 RCG `0x174d0`

## Files

| `FocalTouchProtocol.h/.c` | FTS5652 wire protocol: SPI read/CRC (Kermit CRC16), frame parse, chip ID (0x5652 family) |

## Build integration

Run after `unixnu build kernel`, from the UniXNU tree:

    python3 "$UNIXNU_DEVICE/scripts/build-alioth-touch.py"   # UNIXNU_DEVICE = device checkout

The script compiles the kit with the kernel's own flags (both the
IOPlatformExpert C++ line and the osfmk startup C line, like the sm8550
port), plus `GeniSpi.c` (QcomGeniSpi feed) and `NativeHidInput.cpp`
(ShengHidInput feed), and packs `build/alioth-touch/libNativeAliothTouch.a`.

The HID consumer (NativeHidInput) needs the original IOHIDFamily ABI
generated by the port's HID analysis (build-sheng-hid-input.py): the touch
probe only publishes the finger set (`native_touch_*` seqlock), so the two
must be linked together and the archive merged into the kernel prelink —
the same late-archive step the sm8550 display build uses.

## Runtime

- Panel starts after `touchProbeStart()`: votes clocks, programs SE4 RCG to
  TCXO 19.2 MHz, configures pins, initialises the GENI SPI engine (FIFO),
  releases reset, waits ~9 ms, identifies the chip (reads 0xA3/0x9F/0x90/0xA6).
- The frame loop polls every 6 ms: read command 1 (62 data bytes), verify Kermit
  CRC16, parse 10 contacts, map raw 12-bit coordinates onto the
  `FTS5652_AXIS_X/Y` (0.1 mm) grid, publish with a seqlock.
- Logging: set `native_touch_error`/`native_touch_fail_step`/`native_touch_frames`
  for the boot log (kits/alioth-touch values: fail step 1 map, 2 clocks,
  3 info, 4 fifo, 5 engine, 6 setup, 7 clock, 8 identify, 9 thread).

## Verifying on device

Fastboot boot the payload, then read the boot log or check the touch probe
counters: frame loop active means `native_touch_frames` increases and a finger
press yields `native_touch_count` > 0 with `native_touch_last_x/y` set.
